Components

01

Global header

The header is the component the brief singles out. On the current site every dropdown parent is javascript: void(0); — it has no destination, cannot be reached by keyboard, and announces no state. This replaces it with the WAI-ARIA disclosure navigation pattern.

The structural fix

Current site <a href="javascript: void(0);">Events</a> — one element tries to be both a label and a trigger. It is not focusable in a useful way, has no aria-expanded, and there is no page behind “Events” at all.
New header A real link to a real section landing page, plus a separate sibling button that owns aria-expanded and aria-controls. Pointer users still get hover; keyboard and screen-reader users get an announced, operable control.

Signed-in state

Requirement §3 makes member self-service a core journey — log in, update personal details, update payment method, view membership status, reach the video library and the journal. Signing in swaps Log in and Join for an account menu; Donate stays, because a member may still give. It reuses the same panel component as the main navigation, so there is one dropdown to maintain and one keyboard contract to test.

Keyboard contract

Keyboard behaviour of the global header
KeyWhereResult
TabAnywhereSkip link first, then logo, then each top-level link and its chevron button in reading order.
EnterTop-level linkGoes to the section landing page. The parent is never a dead end.
Enter / SpaceChevron buttonOpens the submenu and sets aria-expanded="true". Any other open submenu closes.
TabInside an open submenuMoves through the submenu links, then leaves and closes the panel behind you.
EscapeAnywhere in the navCloses the open submenu and returns focus to its button. With nothing open on mobile, closes the drawer.

Responsive behaviour

Mobile & tablet · under 1280px

Utility bar hidden. A labelled Menu button opens a full-width drawer; submenus expand inline as accordions. Log in, Join and Donate stack full width at the bottom. Body scroll locks while the drawer is open.

Desktop · 1280px and up

Utility bar appears. Six top-level items sit on one row with hover and click both opening panels. Panels for the right-hand items anchor to their right edge so a wide panel cannot run off screen.

On scroll

The header is sticky at every width. Past 8px of scroll a shadow replaces the hairline rule, so the bar reads as floating above the page rather than sitting on it. Nothing resizes or collapses.

Without JavaScript

An inline script in <head> adds a js class before first paint. If scripting is unavailable the chevron buttons and the Menu button are hidden rather than left as dead controls. On desktop the six top-level links remain, each leading to a landing page that lists the same children. On mobile the whole navigation renders in the document flow with every submenu expanded, so nothing is unreachable.

02

Global footer

The footer does three jobs at once: it is the site’s second navigation for people who scrolled rather than searched, it carries the trust signals a charity is judged on, and it is where the regulatory obligations live. It is built as three stacked bands so a page can drop any one of them.

Bands

The bands that make up the footer region
BandClassWhen it appears
Sponsor strip.tc-sponsors__gridMost pages. Optional per page, since it is a component rather than part of the footer proper.
Newsletter.tc-newsletterMost pages. Suppressed on the signup confirmation and inside the member area.
Footer main.tc-site-footer__mainEvery page. Brand, mission, contact and four link columns.
Legal band.tc-site-footer__legalEvery page. Charity registration, policy links, social, back to top.

Consent, not assumption

The newsletter signup uses an explicit, unticked consent checkbox with the purpose written next to it, and names the unsubscribe route up front. The current site collects subscribers through a bare “Subscribe” button with no consent statement, and its cookie notice links to Kartra’s policies rather than the charity’s — both are UK GDPR and PECR exposures the rebuild has to close.

Accessibility decisions

Accessibility decisions in the footer
DecisionWhy
One nav landmark, four headingsFive separate navigation landmarks would clutter a screen reader’s landmark list. One labelled nav with a heading per column reads better.
Contact as a description listAddress, phone and opening hours are label/value pairs, so dl conveys the relationship that a stack of paragraphs loses.
Social links are 44 × 44pxIcon-only targets, each with visually hidden text naming the network. The icon alone is never the accessible name.
Every colour measuredThe lowest-contrast text in the footer is the legal line at 6.35:1 on the navy ground; body text sits at 10.7:1. Both clear AA.
Back to top is a link, not a buttonIt moves to a document fragment, so it belongs in the same category as any other in-page link and works without JavaScript. The target is a zero-height #top anchor at the start of <body> — not the header, which is sticky and therefore already at the top of the viewport, so jumping to it would scroll nowhere.

WordPress mapping

How the footer converts to WordPress
PrototypeWordPress
Whole footerfooter.php → template-parts/footer.php
Four link columnsFour registered menu locations: footer-about, footer-education, footer-membership, footer-support
Mission, contact, charity numberACF options page — one field group shared with the utility bar
Sponsor stripACF repeater on the options page: logo, name, tier, URL. Per-page toggle to hide it.
Newsletter formBeacon CRM later; today it posts nowhere

Two things to confirm

The footer reads © 1996–2026, matching the About copy. The live site’s footer says © 1994. And the sponsor tiles are text placeholders until logo files arrive — the component contains and never crops them, so mixed aspect ratios are safe.

03

Breadcrumb

Appears on every page except the homepage. It matters more here than on most sites: the current Kartra URLs are opaque strings like ?asset=page&id=HFkV8bxegqrK, so visitors have no way of knowing where they are. The breadcrumb restores that, and it feeds the structured data that puts a readable path in search results.

Standard, three levels
  1. Home
  2. Education
  3. CPD webinars
Deep, with a long final title — wraps rather than scrolls
  1. Home
  2. Education
  3. Webinars
  4. Video library
  5. Health in Motorsport: medical lessons from the Isle of Man TT
On a dark hero
  1. Home
  2. Events
  3. The Annual Conference
Do Keep the last item a link carrying aria-current="page", as the ARIA Authoring Practices recommend. It announces position without making the trail inconsistent.
Don't Type > or / between items. Separators are drawn in CSS, so a screen reader is not made to read “greater-than” five times before reaching the page title.

How it behaves

Listing behaviour and rationale
DecisionWhy
Filters are a form that submits by GETFiltering works with JavaScript off, and every filtered view has a shareable URL. Updating results without a reload is an enhancement layered on later.
Sidebar collapses below 900pxIt becomes a disclosure with a count badge. Above 900px the panel is pinned open and the button is removed, so the state can never be left wrong.
Result count is role="status"When results change, the new count is announced without stealing focus.
Active filters shown as chipsRemoving a filter takes one click from the results, not a return trip to the sidebar. Each chip's hidden text reads “remove this filter”.
Option counts beside each filterNobody should apply a filter to discover it returns nothing.
Every page has its own URLPagination is real links, not scripted. That is what the SEO requirement and the Kartra redirect map depend on.
Previous/Next carry wordsBelow 520px the label is clipped, not deleted, so the control keeps its accessible name.
Members-only badge on the cardRestriction is visible before the click, with a padlock and the words — never colour alone.
